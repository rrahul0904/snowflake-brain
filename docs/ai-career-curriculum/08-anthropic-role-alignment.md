# Anthropic Role Alignment

Anchor: **Data Engineering Manager, Product**. Job details can change; validate the current posting before applying. Courses do not replace management experience. The strategy is to translate existing leadership evidence and add AI-product depth.

## Requirement-To-Evidence Matrix

| Capability | Evidence to present | Portfolio proof |
|---|---|---|
| Product-data engineering leadership | Platform scope, adoption, quality and business outcomes | P1 charter, roadmap, SLO dashboard |
| Product-event architecture | Versioned contracts across consumer, coding, enterprise and API surfaces | P1 event taxonomy and compatibility tests |
| Canonical datasets/marts | dbt facts, dimensions, semantic metrics and reconciliation | P1 lineage and metric catalog |
| SQL/Python | Performance-aware transformations and reliable services | P1 code/tests/benchmarks |
| Data quality and SLAs | Ownership, freshness, correctness, incident response | P1 quality gates and postmortem |
| Self-service analytics | Governed access and measurable adoption | P1 semantic layer/copilot |
| Product/Data Science partnership | Prioritization and experiment operating model | Metric council and experiment review |
| Hiring/team development | Team design, scorecards, coaching and promotion evidence | Leadership templates and stories |
| Claude-powered analytics | Grounded answers over governed marts | P1 copilot eval report |
| AI telemetry | Model, token, latency, cost and tool-use schema | P1 telemetry marts |
| Executive communication | Decision clarity, risk and investment framing | Executive deck and roadmap |

## Gap-Analysis Template

For each capability record: current evidence; scale; quantified outcome; stakeholders; conflict/trade-off; what is missing; 30-day artifact; interview narrative; reference who can validate it.

## Eight Required Leadership Stories

1. Built or materially modernized a data platform.
2. Resolved a product-metric or ownership conflict.
3. Led a high-severity data/reliability incident.
4. Raised quality through standards and automation.
5. Hired/coached a team and improved its operating model.
6. Influenced an executive roadmap with data.
7. Made a difficult architecture or cost trade-off.
8. Delivered across Product, Data Science, Security and Engineering.

Each story needs context, personal decisions, alternatives rejected, measurable outcome and what changed in the organization afterward.

## Architecture Interview Topics

Event contracts; identity/account modeling; late/duplicate events; streaming vs batch; canonical metrics; data access; lineage; freshness/SLOs; experimentation; multi-region reliability; AI traces; token/cost attribution; self-service boundaries; incident recovery.

## Product-Metrics Topics

Activation by surface; retention and habit; team/enterprise adoption; API developer success; coding-assistant acceptance; model quality proxies; tool success; cost-to-serve; latency impact; guardrail metrics; experiment guardrails and metric gaming.

## 30/60/90-Day Outline

- **0-30:** listen, inventory consumers/sources, map critical metrics and incidents, understand team health and establish decision cadence.
- **31-60:** agree priorities/SLAs/ownership, fix one trust bottleneck, define product-event and AI-telemetry architecture, start hiring/coaching actions.
- **61-90:** ship a canonical data-product slice, publish quality/adoption scorecard, establish metric council and present the 12-month platform roadmap.
